# 모여락 홈페이지

성균관대학교 중앙 밴드 동아리 모여락. **Cloudflare Pages(정적 홈페이지 및 관리자 API)** + **Firebase Auth/Firestore(Spark 무료)** 구성.

- 회원용 홈페이지: Cloudflare Pages 프로젝트의 `*.pages.dev` 주소
- 인증: 기존 Firebase Authentication 유지 (학번 + 비밀번호)
- 데이터: 기존 Firestore 유지
- 역할별 부원 관리 API: Cloudflare Pages Functions `/api/members/*` (기존 Firebase Cloud Functions는 사용하지 않음)

## 1. Cloudflare Pages 최초 연결

Cloudflare Dashboard → **Workers & Pages → Pages → Connect to Git**에서 GitHub `skwodnjs/skku-myrock` 저장소를 연결합니다.

| 항목 | 설정 |
|---|---|
| Project name | `skku-myrock` (사용 가능한 경우) |
| Production branch | `main` |
| Root directory | 저장소 루트 `/` |
| Framework | React (Vite) |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Node.js | 22 이상 |

이 저장소의 루트 `functions/api/members/`는 **Cloudflare Pages Functions**입니다. Git 통합 배포 시 Pages가 이 경로를 인식해 `/api/members/list`, `/api/members/sessions`, `/api/members/details`, `/api/members/preview`, `/api/members/register`, `/api/members/permissions`, `/api/members/reset-password`, `/api/members/delete`, `/api/members/purge` API를 배포합니다.

`public/_routes.json`은 Vite가 `dist/_routes.json`으로 복사합니다. **`/api/*`만 Pages Functions 요청으로 집계**하고 HTML/CSS/JS/정적 이미지 요청은 Pages 정적 자산으로 제공하도록 지정합니다.

기존 Firebase Hosting GitHub Actions는 제거했습니다. 예전에 배포된 `skku-myrock.web.app` 주소는 Firebase Hosting에서 수동으로 삭제하지 않는 이상 그대로 남아 있을 수 있지만 **최신 변경 사항은 Cloudflare Pages에 배포**합니다.

### Git 통합 확인

Cloudflare Pages 프로젝트 → **Deployments**에서 `main` 최신 커밋 배포가 **Success**인지 확인하세요. 설정이 `workers.dev`가 아니라 **Pages 프로젝트**인지도 확인합니다.

### 배포 확인용 주소

Pages에서 실제 할당한 주소를 사용해 `https://<프로젝트>.pages.dev/api/health`에 접속합니다. 다음과 같은 JSON이 표시되면 Pages Functions가 배포된 것입니다.

```json
{"service":"myrock-pages-api","deployed":true,"firebaseSecretConfigured":false}
```

`firebaseSecretConfigured: false`는 관리자 서비스 계정 Secret이 없다는 뜻입니다. 대시보드에 `FIREBASE_SERVICE_ACCOUNT`을 저장하고 **재배포하면 true**가 되어야 합니다. 이 점검은 Secret 존재만 검사하며 실제 Firebase API 호출 성공까지 보장하지 않습니다. HTML 홈페이지가 나타나거나 404가 나오면 Pages Functions가 아직 배포되지 않았거나 빌드 설정을 확인해야 합니다.

## 2. Firebase 인증 도메인 추가

Firebase Console → Authentication → Settings → **Authorized domains**에 **실제 발급된** `<your-project>.pages.dev` 도메인을 추가합니다. 주소에 `https://`를 포함하지 않습니다.

기존 Firebase Auth 계정, 비밀번호, Firestore 문서는 이전하지 않고 그대로 유지합니다. 로그인은 Firebase JS SDK로 처리하므로 기존 `authDomain` 설정을 유지합니다.

## 3. Cloudflare 비밀키 연결 (필수)

운영진 API는 Firebase 서비스 계정으로 Google REST API를 호출합니다. 학번 변경은 Auth 이메일도 업데이트해야 하고 회장단의 비밀번호 초기화·회원 삭제에는 Firebase Authentication Admin의 사용자 업데이트·삭제 IAM 권한이 필요합니다. **클라이언트 코드나 GitHub에 서비스 계정 키를 절대로 저장하지 마세요.**

1. Firebase 프로젝트 `skku-myrock`에 접근 가능한 서비스 계정을 준비합니다. 최소 권한 관리를 위해 **Firebase Authentication Admin** 및 **Cloud Datastore User** 등 계정 생성·조회·삭제와 Firestore 문서 조회·생성·수정에 필요한 IAM 역할만 부여하는 전용 서비스 계정을 권장합니다.
2. 서비스 계정 JSON은 자신의 컴퓨터에만 저장합니다. 현재 Firebase Admin SDK에서 사용한 키를 임시로 재사용할 수도 있지만, 장기 운영에는 전용 키를 권장합니다.
3. Cloudflare → **Workers & Pages → 해당 Pages 프로젝트 → Settings → Variables and Secrets → Add**에서 다음을 생성합니다.

   | 이름 | 설정 | 값 |
   |---|---|---|
   | `FIREBASE_SERVICE_ACCOUNT` | **Encrypt/Secret** | 서비스 계정 JSON 전체 내용 |
   | `FIREBASE_API_KEY` | 일반 환경 변수 (선택) | Firebase 웹 API key. 코드에 기존 공개 Firebase 구성값을 기본으로 사용 |

4. **Production** 환경에 설정하고 **새 배포를 실행**해야 Functions 런타임에 반영됩니다. Preview 배포도 테스트하려면 Preview 환경에 별도로 지정해야 할 수 있습니다.
5. Cloudflare Pages 무료 할당량에 맞춰 각 요청에서는 회원 **최대 5명**씩 처리하며, CSV가 60명인 경우 웹이 자동으로 여러 요청으로 나눠 처리합니다.

서비스 계정 JSON 파일을 ChatGPT 대화, GitHub, 공개 페이지나 Cloudflare 일반 평문 변수에 붙여 넣지 마세요. **Secret**으로만 설정합니다. 계정 소유자 또는 개발 담당자만 이 설정을 관리하고, 일반 운영진에게 키를 넘기지 않습니다.

> **주의:** 비밀키가 없거나 Google Cloud IAM 권한이 부족하면 홈페이지 정적 페이지는 표시되지만 회원 관리 API는 실행되지 않습니다. 이 저장소 변경만으로 사용자의 Cloudflare Secret과 Firebase Authorized domains를 대신 설정할 수 없습니다.

## 4. CSV 부원 등록 절차

로그인한 회장단이 **부원 관리 → 신입부원 등록**에서 다음 3단계를 수행합니다.

1. **CSV 추가:** 양식을 받거나 UTF-8 CSV 파일 선택 (한 번에 최대 60명).
2. **추가될 명단 확인:** 실제 생성에 앞서 Firebase에서 기존 학번 존재 여부를 조회하고 **신규 등록 예상 인원·기존 계정 수·학번·이름·기수·세션·직책 전체를 표로 확인**. 이 단계에서는 어떠한 회원도 생성하지 않음. 다른 파일로 바꿀 수 있음.
3. **등록 실행 → 등록 완료:** 웹이 5명 단위로 요청을 처리하며 진행률을 **0~100%**로 표시하고, **신규 생성/기존 계정/실패** 결과를 구분합니다. 새 계정의 초기 비밀번호는 학번 10자리와 같습니다.

양식 예시:

```csv
학번,이름,기수,세션,직책
2026300001,홍길동,29,"기타,베이스",
2026300002,김모여,29,드럼,"장비관리,홍보부장"
```

영문 헤더 `studentId,name,generation,sessions,positions`도 지원합니다. **세션과 직책의 여러 값은 쉼표로 구분**합니다. `"기타,베이스"`와 `"기타, 베이스"`는 모두 `기타`·`베이스`로 해석하며, 결과를 화면에 표시할 때는 `기타,베이스`처럼 쉼표 뒤 공백이 없는 표준 형식으로 표시합니다. 직책도 동일합니다. **CSV의 열 구분자도 쉼표이므로 여러 값을 담은 셀 전체를 반드시 큰따옴표로 감싸야 합니다.** (예: `"보컬파트장,홍보부장"`)

- **실제 회원 생성은 2단계에서 관리자가 등록 실행을 누른 뒤에만 진행됩니다.** 신규/기존 계정 수는 파일을 확인한 시점의 예상치이며, 동시에 다른 관리자가 등록하면 실제 결과가 달라질 수 있습니다.
- 새 계정은 언제나 `role: member`, `handoverAccess: false`. `generation`과 `positions`는 표시용 데이터입니다.
- 기존 학번이 이미 있으면 계정·프로필·비밀번호·권한을 수정하지 않고 건너뜁니다.
- 통신 장애 시 결과를 확인할 수 없는 계정이 존재할 수 있으므로 **무작정 같은 명단을 재시도하지 말고 회원 명단과 관리자 로그를 확인**하세요.
- **신규 생성 계정**은 초기 비밀번호가 **본인 학번(10자리)**입니다. 초기 비밀번호 CSV 파일을 따로 내려받을 필요는 없습니다. 기존 계정의 비밀번호는 변경하지 않습니다. 로그인 문제가 생기면 운영진에게 연락하도록 안내합니다. 비밀번호는 로그인 후 **내 정보 → 비밀번호 변경**에서 본인이 변경할 수 있습니다.
- 계정 생성과 Firestore 프로필 생성은 별도 Google 서비스 작업이므로 일부 실패가 가능하며, 서버는 신규 계정 롤백을 시도합니다.

부원 관리에서 **파트장·실무단에게는 부원 명단 탭만**, **회장단에게는 부원 명단 및 신입부원 등록 탭**을 표시합니다. 부원 명단은 Firestore의 `name asc, __name__ asc` 정렬 인덱스를 사용해 **처음 30명만 조회**하고, 하단으로 스크롤하면 `IntersectionObserver`가 다음 30명을 자동으로 불러옵니다. 전체 이름순으로 정렬된 결과를 페이지별로 받아 한 화면에 이어 붙입니다. 스크롤 중 목록 요청에 실패하면 자동 재시도를 멈추고 사용자에게 재시도 버튼을 제공합니다. 한국어 완성형 이름은 일반적인 가나다순으로 표시되지만 Firestore 문자열 정렬은 완전한 한국어 사전 정렬과 일부 다를 수 있습니다. **검색은 아직 불러온 명단에만 적용됩니다.** 수정 기능은 부원 행 아래에 바로 표시되며 별도 권한 관리 탭은 없습니다.

## 5. 부원 관리 권한

서버는 Firebase ID 토큰 및 Firestore 프로필을 **요청마다 다시 검증**합니다. 화면에서 버튼을 숨기는 것 외에도 서버 API에서 역할별로 거절합니다.

| 기능 | 파트장 | 실무단 | 회장단 |
|---|---|---|---|
| 부원 명단 전체 조회 (가나다순) | 가능 | 가능 | 가능 |
| 타 부원 세션 수정 | 가능 | 가능 | 가능 |
| 이름/학번/기수/직책 수정 | 불가 | 가능 | 가능 |
| CSV·개별 부원 추가 | 불가 | 불가 | 가능 |
| 권한 / 인수인계 지정 | 불가 | 불가 | 가능 |
| 비밀번호 초기화 (현재 학번 10자리) | 불가 | 불가 | 가능 |
| 부원 삭제 (Auth 계정 + Firestore 프로필) | 불가 | 불가 | 가능 |

**OB 운영진**은 `handoverAccess: true`이면서 `role: member`이면 내 정보의 권한에 OB 운영진으로 표시하지만, **부원 명단 조회 및 수정 권한은 부여하지 않습니다.** 현재 최고관리자만 기존 custom claim과 Firestore flag를 함께 검사해 회장단 수준으로 관리할 수 있습니다.

**내 정보 → 권한**은 `회장단`, `실무단`, `파트장`, `OB 운영진`, `일반부원` 중 한 가지로 표시합니다. 직책은 별도 필드로 표시합니다.

학번을 수정하면 `학번@members.skku-myrock.firebaseapp.com`로 되어 있는 Firebase Auth 로그인용 이메일까지 변경하고, Firestore 저장에 실패하면 Auth 값을 되돌리도록 시도합니다. 학번 변경 시 **비밀번호는 자동 초기화되지 않습니다.**

회장단이 비밀번호를 초기화하면 해당 부원의 비밀번호가 **현재 학번 10자리**로 바뀝니다. 계정 삭제는 학번 재입력 확인을 요구하며 시스템 관리자와 본인 계정은 삭제할 수 없습니다. 삭제 작업은 Auth와 Firestore가 서로 다른 서비스이므로 오류 발생 시 복구 확인이 필요할 수 있습니다. **하위 컬렉션/다른 게시물 데이터까지 자동 정리하는 기능은 포함하지 않습니다.**

비밀번호 변경 화면에서는 사이트 자체의 최소 길이·조합 제한을 두지 않습니다. 단, **Firebase Auth 서버 자체의 최소 6자 제한**은 유지됩니다.


- `role`: `member`, `part_leader`, `staff`, `president` (기수로 자동 변경되지 않음)
- `positions`: 표시용 직책 목록
- `handoverAccess`: 다른 권한과 독립적인 인수인계 접근 여부

Firebase 로그인 토큰 서명·대상 프로젝트·만료 시간 및 Firestore의 현재 회장단 권한을 **Cloudflare 서버에서 검증**합니다.

현재 개발용 최고관리자 계정은 유지되며, **최고관리자를 새로 발급하거나 수정하는 API는 제공하지 않습니다.** 웹에서 자기 자신이나 기존 최고관리자 계정의 권한 변경을 금지합니다.

세션 수정·자기 비밀번호 변경은 기존 Firebase SDK에서 진행합니다. 신규 회원에게 학번과 동일한 초기 비밀번호를 지정하는 방식은 추측 가능하므로, 계정에 문제가 있다면 운영진에게 문의하고 필요한 경우 본인이 변경하는 것을 권장합니다. 자동 최초 로그인 변경은 강제하지 않습니다. 현재 이메일은 실제 수신함이 아닌 `학번@members.skku-myrock.firebaseapp.com` 주소로, 이메일 재설정은 지원하지 않습니다.

Firestore 보안 규칙 `firestore.rules`는 자기 프로필만 읽고 세션만 직접 수정하도록 제한합니다. 운영진 작업은 보안 규칙을 우회할 수 있는 서비스 계정으로 수행하므로 **Cloudflare Functions 내부에서 관리자 권한을 반드시 확인합니다.**

### 개발용 최고관리자 명단 초기화

Firebase ID 토큰의 `superadmin: true` **서명된 사용자 지정 클레임과** 해당 사용자의 Firestore `superadmin: true` 필드가 **모두 확인되는 계정에만** 계정 드롭다운의 **로그아웃 바로 아래 빨간색 '명단 초기화'**가 표시됩니다. 보통 회장단이나 OB 운영진 계정에는 보이지 않습니다. 휴대폰 메뉴에서도 같은 조건으로 표시합니다.

- 버튼 클릭 뒤 브라우저 확인창에서 **확인**을 누른 경우에만 실행됩니다.
- 서버는 이 두 최고관리자 조건을 독립적으로 재검증하며, 프런트엔드가 삭제 대상 UID를 전달할 수 없습니다.
- 본인의 Firestore `users/{uid}`와 Firebase Authentication 계정은 보존하고 **다른 부원의 프로필 및 연동된 Auth 계정**을 최대 **5명씩** 처리합니다. 삭제 결과를 표시하고 중간 실패가 발생하면 중단합니다. 다시 실행할 경우 남은 명단부터 진행합니다.
- 다른 `superadmin: true` 프로필이 발견되는 경우 보호를 위해 작업을 중단합니다.
- Firebase Auth 계정 없이 프로필만 남은 경우에는 해당 프로필을 정리합니다. **프로필 없이 Firebase Auth에만 존재하는 계정은 이 기능에서 검색/삭제하지 않습니다.**
- 이 기능은 Cloudflare의 무료 실행/외부 요청 한도를 고려한 개발용 관리 도구입니다. **실제 부원 명단이 만들어지기 전에 제거하거나 접근 정책을 재검토하세요.**
- Firestore 문서 삭제는 **하위 컬렉션을 재귀적으로 제거하지 않습니다.** 현재 구현에서 별도의 하위 컬렉션 생성 기능은 없지만, 수동으로 만든 하위 컬렉션이나 앞으로 추가하는 When2meet·게시물·장비 대여 기록은 이 명단 초기화로 삭제되지 않을 수 있습니다.

### 수동 명단 초기화 후 점검

1. Firebase Console → **Authentication → Users**에서 보존할 최고관리자 외에 이전에 발급한 부원 계정이 남았는지 확인합니다.
2. Firestore → **Data → users**에서 보존할 최고관리자 외 문서가 남았는지 확인합니다. 문서 아래 하위 컬렉션을 직접 생성했던 경우 개별 확인이 필요합니다.
3. 테스트 중 다른 Firestore 컬렉션, Cloud Storage 업로드 파일, 외부 서비스 데이터 등을 생성한 경우 해당 데이터는 각각 별도로 확인합니다.
4. `FIREBASE_SERVICE_ACCOUNT` 서비스 계정 키와 최고관리자의 Firebase 사용자 지정 클레임은 삭제할 필요가 없습니다. 명단 초기화는 Firebase 프로젝트 자체를 삭제하는 작업이 아닙니다.

## 포토존 (공연·행사·일상 앨범)

- `src/galleryData.ts`에서 공연 6건, 행사 2건, 일상 2건의 **행사 단위 앨범**을 정의합니다.
- 각 앨범에 현재는 **실제 이미지가 없는 사진 5~7개 슬롯**을 섞어 지정해 두었습니다. 사진이 준비되면 앨범별 `photos` 목록의 `null`을 이미지 경로로 대체하면 됩니다. 현재는 사진 업로드·Firestore 데이터 연결이 구현되지 않았습니다.
- 포토존 목록에는 앨범당 **첫 번째 사진(대표사진) 하나**만 표시하고, `전체보기`를 선택하면 어두운 배경 위의 사진 뷰어가 열립니다. 앨범 제목이 길어도 **한 줄에서 말줄임표(…)**로 표시하고, 마우스를 올리면 원래 제목을 확인할 수 있습니다.
- 사진 뷰어는 **좌우 버튼, 키보드 좌우 화살표, 터치 스와이프, 하단 위치 표시 점, 오른쪽 세로 썸네일 클릭**을 지원합니다. 좁은 화면에서는 썸네일을 하단 가로 줄로 배치합니다.
- `Escape` 키와 닫기 버튼으로 복귀할 수 있으며 닫으면 이전에 선택했던 앨범 카드로 키보드 포커스를 돌려줍니다.
- 기존 포토존 예시에서 `span` 전체에 적용되던 자동 여백 때문에 사진 자리 텍스트가 오른쪽으로 밀린 문제를 분리된 카드 스타일로 해결했습니다.

## 공지사항 (현재 하드코딩)

- `src/noticesData.ts`에 **2026년 공지사항 4건의 제목·본문 전체·게시일·분류**를 저장합니다. 현재 Firestore 등의 데이터베이스를 연결하지 않습니다.
- 게시일 기준 최신순: **8월 28일 신입부원 모집(공지)** → **8월 21일 보컬 오디션(공지)** → **8월 18일 홈커밍데이(행사)** → **7월 11일 여름 공연(공연)**. 홈 화면에는 최신 3건을 표시합니다.
- 메인 화면이나 공지사항 목록의 항목을 선택하면 `/news/<공지-id>` 상세 페이지로 이동합니다. 링크를 직접 열거나 새로고침해도 해당 글이 표시되며 브라우저 뒤로 가기·앞으로 가기가 지원됩니다.
- 공지사항 페이지에서는 카테고리 필터와 본문 포함 텍스트 검색을 사용할 수 있습니다. 목록의 **글쓰기** 버튼은 추후 데이터 저장 기능을 연결할 예정이므로 현재는 안내만 표시합니다.
- 각 글 본문은 작성자가 전달한 원문 줄바꿈과 내용을 그대로 보존해 출력합니다. 게시글마다 **맨 앞에 실제 사진을 넣을 수 있는 이미지 자리**를 한 개씩 만들고 나중에 파일 경로로 교체할 수 있습니다. 필요하면 이미지 슬롯의 위치를 본문 중간으로 옮겨 확장할 수 있습니다.
- 게시물 데이터는 정적 소스이므로 관리자가 사이트에서 글을 작성하거나 수정하는 기능은 아직 제공하지 않습니다.

## 후원 · 회계 (현재 화면만 구현)

- 메인 `/finance`는 **후원 소개 → 후원 계좌 안내 → 비공개 후원 안내 → 두 내역 상세 페이지** 순서입니다. 후원 계좌의 은행·계좌번호·예금주는 제공받지 않았으므로 **'등록 예정'**으로만 표시합니다. 실제 계좌처럼 보이는 예시 번호는 포함하지 않았습니다.
- `/finance/donations`는 **전체 후원 내역(공개)**과 **내 후원 내역(로그인 필요)**을 분리한 화면입니다. 로그인하지 않은 방문자는 내 내역 대신 로그인 안내를 보며, 로그인해도 지금은 후원 데이터가 없으므로 별도 기록이 나타나지 않습니다.
- `/finance/expenses`는 향후 회비 집행일·항목·상세 내용·금액을 조회할 수 있는 회계 기록 화면입니다. 현재는 빈 목록 UI만 제공합니다.
- 이름 비공개를 요청하거나 입금자명에 `홍길동(비공개)`와 같이 표시한 후원은 공개 내역에서 **익명**으로만 보여주되, 실제 후원 내역을 본인 계정과 확인·연결한 경우 본인만 사적인 후원 내역을 볼 수 있도록 **추후 서버에서 인증/권한 규칙을 적용해야 합니다**. 단순히 입금자명을 이용해 본인 계정을 추측해서 연결하거나 공개 API에서 실제 이름을 함께 제공해서는 안 됩니다.
- 이번 작업에는 **Firestore/Storage/계좌 API/은행 입금 확인/금액 집계/후원자 식별**을 연결하지 않았습니다. 은행 계좌와 결제/후원 기록은 UI 자리만 만들었으며 개발·테스트 과정에서 실제 후원을 받도록 안내하지 않아야 합니다.
- 후원자 개인정보를 향후 공개하려면 본인 동의·비공개 요청 처리 정책을 먼저 확정해야 하며, 공개용 목록과 인증 후 본인용 목록은 **서버에서 구분해 반환**해야 합니다.

## 합주 시간 조율 (현재 목록·상세 미리보기)

- `/schedule` 첫 화면에는 **시간표 만들기**와 **내가 참여한 시간표 4개(예시 데이터)**만 표시합니다. 예시 제목 및 구분은 `src/SchedulePages.tsx`의 `scheduleExamples`에서 관리합니다.
- Firebase Auth 로그인과 기존 Firestore 부원 프로필의 운영 권한(`part_leader`, `staff`, `president`; 검증된 시스템 superadmin 포함)이 확인된 경우 **구성팀 시간표 만들기** 버튼이 추가로 나타납니다. 권한 확인 중에는 표시하지 않습니다. 아직 만들기 기능은 구현하지 않았으며 두 만들기 버튼은 안내 메시지만 표시합니다.
- 각 목록의 **시간표 열기** 버튼은 `/schedule/<시간표-id>`로 이동합니다. 상세 페이지는 제목과 주간 17:00~23:00 예시 가능 시간표를 보여주며 URL 직접 접근, 브라우저 뒤로·앞으로 가기, 목록으로 돌아가기 등을 지원합니다.
- 4개 시간표는 **모두 시각화용 샘플**입니다. 지금은 실제 로그인 사용자와 시간표 소속 관계, 참여 인원, 참석 응답, 시간표 생성, 초대, 저장 및 확정 로직을 연동하지 않았습니다. 실사용시에는 서버에서 참가자 확인과 구성팀 생성 권한을 검증해야 하며, 버튼 표시만으로 보안을 대체해서는 안 됩니다.
